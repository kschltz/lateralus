# Security Policy — Lateralus

## Threat Model

Lateralus is a **local-first Clojure agent framework** designed to run on a developer's machine. It connects to LLM APIs and evaluates code via a local REPL. The primary trust boundary is between **the user's machine** and **the network**.

## Known Security Boundaries

### 🔴 CRITICAL: REPL Eval Tool — Arbitrary Code Execution

**Files:** `src/kschltz/agent/tools/repl.clj`

The `repl-eval-tool` and `repl-nrepl-tool` execute **arbitrary Clojure code** generated by the LLM via `clojure.core/eval`. There is **no sandbox, no allowlist, and no capability restriction**.

- `eval-forms` runs LLM output in a daemon thread with the same JVM permissions as the host process
- The `edamame/parse-string-all` call is for **delimiter repair only**, not security filtering
- Code can access the filesystem, network, and all JVM APIs

**Mitigations in place:**
- REPL eval is **opt-in** — it must be added to an agent's tool list via `add-repl-eval-tool!` or `add-repl-nrepl-tool!`
- Eval has a timeout (`LATERALUS_EVAL_TIMEOUT_MS`, default 30s)
- nREPL server binds to `127.0.0.1` only (not `0.0.0.0`)

**Risks:**
- If lateralus runs in **daemon mode** (`-d`) or with the **nREPL server** active, any local process can inject code
- If the agent is exposed as a network service, remote code execution is trivially achievable
- LLM prompt injection could lead to unintended code execution

**Recommendations:**
- Never expose lateralus (or its nREPL port) to untrusted networks
- In production, run without the REPL tool if code execution isn't needed
- Consider adding a `--no-repl` flag to the CLI that disables REPL tool registration

### 🟡 HIGH: nREPL Server — No Authentication

**File:** `src/kschltz/agent/nrepl_server.clj`

The nREPL server binds to `127.0.0.1:59500` with **no authentication**. Any local process can connect and evaluate arbitrary Clojure code.

- Default port is fixed and documented
- nREPL server auto-starts when `repl-nrepl-tool` is used
- No auth token, no TLS, no connection verification

**Mitigations in place:**
- Binds to localhost only (`:bind "127.0.0.1"`)
- Not started unless explicitly requested

**Recommendations:**
- Add optional nREPL auth token (`:nrepl-token` env var)
- Document that nREPL is for development only, not production deployment

### 🟡 HIGH: Daemon Mode PID File — Predictable Path

**File:** `src/kschltz/agent/cli.clj`

`write-pid-file` writes to a predictable path (`.lateralus/session-id.pid`) with a symlink race potential. Only relevant when running in daemon mode (`-d`).

**Recommendation:** Use `java.io.File.createTempFile` or create the PID directory with restrictive permissions (`700`).

## Network Security

### LLM API Communication

**File:** `src/kschltz/agent/http.clj`

- All LLM API calls use `hato` (HTTP client) with TLS certificate verification enabled by default
- API keys are sent via `Authorization: Bearer` header — stored in memory only, passed via `LATERALUS_API_KEY` env var or `-k` CLI flag
- API keys are **never logged** or written to disk by lateralus itself
- **No SSRF protection** — `LATERALUS_BASE_URL` can point to any URL including internal services. This is by design (user-controlled config) but means a compromised env var could enable internal network scanning

### Web Search Tool

**File:** `src/kschltz/agent/tools/web.clj`

- Web search only accesses fixed hardcoded URLs (Mojeek, Startpage, Wikipedia)
- User queries are passed as URL parameters, properly encoded
- No arbitrary URL fetching capability — **no SSRF risk from LLM output**

### Embedding Service

**File:** `src/kschltz/agent/memory/embedding.clj`

- Default method (`langchain4j`) runs **in-process** — no network calls, no data leaves the machine
- HTTP mode (`LATERALUS_EMBEDDING_METHOD=http`) sends conversation text to the configured embedding endpoint
- **Ensure the embedding endpoint is trusted** when using HTTP mode

## Data at Rest

### Session Storage — No Encryption

**File:** `src/kschltz/agent/memory/datalevin.clj`

- Session data (full conversation histories, tool call transcripts) is stored in Datalevin databases on disk
- **No encryption at rest** — anyone with filesystem access can read all conversation data
- Default session directory is `sessions/` (gitignored)
- Session IDs are user-chosen strings (default: `"default"`)

### API Keys in Memory

- API keys are held in agent state (an `agent` atom) during the process lifetime
- They are passed to `hato` HTTP calls and never written to disk by lateralus
- **Not scrubbed from memory** after use — standard JVM string retention applies
- The `-k`/`--api-key` flag passes the key via CLI arguments, which may be visible in process listings (`ps aux`). Prefer `LATERALUS_API_KEY` env var.

### Dependencies

|---|---|---|
| org.clojure/clojure | 1.12.5 | |

**Recommendations:**
- Pin dependency hashes in `deps.edn` for reproducibility
- Monitor CVEs for `datalevin` (embedded DB) and `hato` (HTTP client)
- Consider running `clj-watson` or `clj-kondo` with security linting
